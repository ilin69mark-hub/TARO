# Контракт артов карт (T24)

Файлы лежат здесь: `public/cards/*.webp` (500×800 px, 5:8, WebP ≤90KB).
Имя файла = `image_key` из таблицы `cards` (см. сид 002). Код подхватывает без изменений.

## Контракт имён (обязателен к соблюдению)

`image_key` в БД начинается с `cards/`, и компонент собирает путь как `/` + `image_key`,
то есть файл ожидается именно в `public/cards/`. Все 78 ключей сида имеют вид
`cards/major-NN-slug.webp` и `cards/minor-<suit>-<rank>.webp`. Allowlist в
`web/components/CardArt.tsx` обязан это учитывать — иначе компонент тихо рисует
fallback-рубашку вместо карты. Golden-тест на все 78 ключей: `web/components/CardArt.test.tsx`.

## Статус (на 2026-09-28)

**Файлов 78 из 78 + `card-back`.** Контракт соблюдён, тест проверяет это на каждом
прогоне (существование файла, сигнатура RIFF/WEBP, геометрия 500×800, бюджет 90KB).

- [x] 22 старших аркана (`major-00…major-21`)
- [x] 56 младших (`minor-{wands,cups,swords,pentacles}-{ace,02..10,page,knight,queen}`)
- [x] `card-back` (рубашка)
- [x] контракт имён и путей (A05/F-04: раньше расходился с сидом, арты не рендерились никогда)

Исходники при поставке были PNG ~992×1585 (242 МБ) с именами вида `01_magician_ru.png` /
`22_cups 02_ru.png`. Приведение к контракту: центральный кроп до 5:8 → ресайз 500×800 →
WebP, качество подбиралось по файлу (78 вниз до 44) ради бюджета 90KB. Итог 6.9 МБ.

**Внимание при будущих заливках:** маппинг идёт по слагу, а не по номеру в имени.
В исходниках `12_death_ru.png` и `13_hanged_ru.png` были пронумерованы наоборот
(сид: 12 = hanged, 13 = death). Исходные PNG-файлы удалены 2026-09-28 после проверки —
это единственная копия, перегенерация потребует новой генерации.

Проверка: `npx vitest run components/CardArt.test.tsx`.
